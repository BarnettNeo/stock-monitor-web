### 核心原则：

“能不用大模型就不用”
“长链路只在最终回答阶段使用强模型”
“Embedding 优先稳定和中文效果”
“抓取/清洗阶段尽量传统 NLP + 小模型”

#### 场景本质上是：

Ingest Worker = 偏工程流水线（低推理）
Retrieval Worker = 中等推理 + 引用归因
Thinking Worker = 强推理 + 生成

### 1. Ingest Worker（新闻抓取）
职责：

- RSS 抓取
- HTML 正文抽取
- 去广告
- 标题规范化- 
- chunk 切分
- embedding
- 写入 Milvus

完整链路：
RSS/JSON 抓取 → HTML 正文抓取 → 文本清洗 → 股票代码匹配 → 文本切片 → Embedding向量化 → Milvus写入
  
推荐 Prompt：

- “提取新闻核心内容”
- “生成 3 个标签”
- “判断是否为重复新闻”


为什么用轻量模型？

```Python

# 任务特点：
# - 输入：RSS feed + HTML 正文
# - 输出：结构化 JSON（标题、正文、时间、来源）
# - 不需要深度推理，只需模式识别

# 提示词示例（适配 qwen-turbo）
prompt = """
请从以下 HTML 中提取新闻信息，返回 JSON：
{
  "title": "标题",
  "content": "正文（去除广告/导航）",
  "publish_time": "ISO8601",
  "source": "来源"
}

HTML:
{html_content}
"""
```
优化点：

批量处理（10篇/次调用）降低成本
缓存 RSS 结果，避免重复抓取
异常 HTML 才升级到 Plus 模型
### 2. Retrieval Worker（检索归因）

职责：

- query rewrite
- 检索
- rerank
- citation attribution
- 时间排序
- 来源可信度判断


为什么需要中等模型？

```Python

# 任务特点：
# - 输入：用户 query + 检索到的 top-10 chunks
# - 输出：相关度排序 + 归因引用
# - 需要语义理解，但不需要创造性

# 提示词示例（适配 glm-4-air）
prompt = """
用户问题：{query}

候选片段：
{chunks}

请：
1. 判断每个片段的相关度（0-10 分）
2. 提取支持/反对的关键句子
3. 生成引用格式：[来源名称, 时间]

返回 JSON 数组。
"""
```


优化点：

使用 Function Calling 强制结构化输出
长上下文模型（128k）避免截断
考虑使用 Embedding 模型（文心/智谱）做初筛
### 3. Thinking Worker（最终回答）

职责：

- 汇总
- 推理
- 多新闻综合
- 生成最终答案
- 追问建议

为什么用旗舰模型？

```Python

# 任务特点：
# - 输入：归因结果 + 原始 query
# - 输出：摘要 + 要点 + 追问建议
# - 需要逻辑推理、多角度分析

# 提示词示例（适配 deepseek-chat）
prompt = """
基于以下已归因的信息，回答用户问题：

问题：{query}

信息来源：
{attributed_info}

要求：
1. 总结（100字内）
2. 关键要点（3-5条）
3. 不同观点对比
4. 追问建议（2个）

注意：必须标注引用来源 [n]
"""
```

优化点：

流式输出提升体验
缓存热点问题答案（Redis）
敏感内容用国内合规模型（文心/通义）
